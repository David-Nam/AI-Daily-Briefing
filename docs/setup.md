# Work 반복 실행 설정

확인일: 2026-10-02

## 확인된 것

- GitHub 연결을 통해 저장소 조회는 가능했지만, 파일 생성은 403 Resource not accessible by integration으로 실패했습니다. 저장소 permissions.push 표시만으로 연결 앱의 쓰기 권한을 판단하면 안 됩니다.
- SSH 읽기 접근은 확인되었습니다. 기본 파일은 로컬 Git 경로로 업로드를 진행했습니다.
- 이 준비 작업의 파일 생성 성공은 이후 Work 예약 실행의 권한까지 보장하지 않습니다.
- 현재 반복 예약은 등록하지 않았습니다. 기존 예약도 변경하지 않았습니다.

## 권장: ChatGPT Work 웹에서 GitHub에 직접 저장

1. ChatGPT 웹에서 Work 대화를 엽니다.
2. 해당 대화에서 GitHub 앱/플러그인을 연결하고 파일 쓰기 권한을 확인합니다. 현재 이 대화의 연결 앱은 파일 생성에서 403이 발생했습니다. 쓰기 권한이 제공되지 않는다면 로컬 프로젝트 대안을 사용하세요. David-Nam/AI-Daily-Briefing 접근을 허용합니다. 로그인 및 권한 승인은 사용자가 수행합니다. 메뉴 이름은 계정과 앱 버전에 따라 다를 수 있습니다.
3. 이 저장소의 prompts/daily-briefing.md를 읽고 같은 지시문으로 한 번 실행하도록 요청합니다. 기존 AI Daily Briefing의 전체 프롬프트를 함께 제공하여 관심 분야와 출력 규칙을 유지합니다.
4. GitHub에서 briefing/YYYY/MM/YYYY-MM-DD.md와 커밋을 확인합니다. 채팅 답변만 만들어졌다면 저장 시험은 실패입니다.
5. 시험이 성공하면 같은 대화에서 다음과 같이 요청합니다.

> 위에서 검증한 AI Daily Briefing 작업을 매일 오전 6시 Asia/Seoul에 반복 실행해 주세요. 매번 David-Nam/AI-Daily-Briefing의 prompts/daily-briefing.md를 읽고 날짜별 Markdown을 main에 저장하고 원격 파일을 다시 읽어 확인하세요. 성공 시 파일 링크와 핵심 요약을, 실패 시 원인을 알려 주세요. 저장한 시간대, 실행 위치, 다음 실행 시각을 확인해 주세요.

6. 사이드바 Scheduled(예약 작업)에서 저장된 프롬프트, 일정, 활성 상태, 실행 기록을 확인합니다. 처음 몇 회는 파일 생성까지 확인합니다.
7. 새 흐름이 정상 작동하면 기존 AI Daily Briefing 예약을 일시 중지하여 중복 생성을 방지합니다.

오전 6시는 설정 예시입니다. 실제 시간은 사용자가 선택합니다.
웹 Work에서 필요한 GitHub 쓰기 도구가 보이지 않거나 반복 실행에서 쓰기가 차단되면 이 방식은 아직 사용할 수 없습니다.

## 대안: 데스크톱 로컬 프로젝트

1. 이 저장소를 로컬에 clone합니다.
2. 데스크톱 앱에 clone한 폴더를 프로젝트로 추가하고 해당 폴더의 Work 대화를 엽니다.
3. Git 인증과 원격 push가 가능한지 시험합니다. 폴더 접근 및 로그인 승인은 사용자가 수행합니다.
4. 실행 지시문으로 실제 파일 작성, 해당 파일만 커밋, push, 원격 재확인을 한 번 시험합니다.
5. 같은 대화에서 원하는 일정으로 반복 실행을 요청하고 Scheduled에서 확인합니다.
6. 실행 시 Mac이 켜져 있고 앱이 실행 중이어야 합니다. 로컬 checkout은 GitHub 저장과 별개의 실행 환경입니다.

## 역할 구분

- Work가 수행: 자료 조사, Markdown 작성, 제공된 도구를 통한 파일 생성·커밋, 저장 확인, 예약 생성·수정 요청 처리.
- 사용자 수행: GitHub 로그인/권한 승인, 실행 위치와 시각 선택, 필요한 프로젝트 폴더 추가, 최초 결과 확인.
- 이 대화에서 이미 수행: 저장소 접근 확인과 기본 파일 준비.
- 아직 미수행: 기존 예약 프롬프트 이관, 실제 뉴스 시험 실행, ChatGPT Work 웹의 예약 생성 및 실행 검증.
