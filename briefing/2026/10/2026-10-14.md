# Session 2 — AI Development Trend Radar

## 1. Agent-scale source control: Git을 바꾸기보다 checkout·merge 병목을 계측

**What it is / Problem:** 대량의 coding agent가 수많은 독립 변경을 생성할 때 Git clone, CI checkout, merge queue, review throughput이 병목이 되는 현상이다.

**How developers use it:** Anthropic은 Scion에서 server-side changeset, content-addressed object, sparse checkout, source-control API, 디렉터리별 권한을 결합했다. 일반 팀에서는 Git worktree, partial clone, sparse checkout, CI cache, branch-per-agent가 우선적인 대안이다.

**Recent delta:** 10월 13일 Anthropic이 하루 30,000건 이상 merge와 Scion 운영 경험을 공개했다. 자체 보고에 따르면 checkout이 분 단위에서 초 단위로 단축됐지만 특수한 monorepo 규모에서의 결과다.

**Evidence / limitations:** 생산 환경 사례이나 단일 기업의 자체 수치다. Scion 자체도 일반용 Git 대체재가 아니라고 명시한다.

**Trend direction:** Growing. **Maturity:** Production practice at extreme scale / broader adoption experimental.

**Sources:** [Anthropic — Scion architecture](https://www.anthropic.com/engineering/redesigning-source-control?utm_source=chatgpt.com) · [VS Code 1.141 worktree 관리](https://code.visualstudio.com/updates/v1_141?utm_source=chatgpt.com)

## 2. Code generation보다 review·acceptance throughput을 측정

**What it is / Problem:** 코드 생성 속도와 실제 완료된 소프트웨어의 양은 다르다. Review와 검증이 뒤따르지 않으면 PR 대기열만 늘어난다.

**How developers use it:** Agent별 lines of code 대신 issue closure, review elapsed time, rework rate, CI failure, rollback, post-deploy defect를 측정한다. 명세와 acceptance test를 먼저 작성하고 작은 변경 단위로 나눈다.

**Recent delta:** 10월 9일 보도로 재조명된 Harvard/Jellyfish의 718개 기업 연구에서 agent 도입 후 코드량 약 30%, commit 약 20%, PR 약 23% 증가가 관찰됐다. 반면 issue·epic 완료 건수의 통계적으로 유의한 증가는 확인되지 않았고 PR 제출부터 merge까지의 경과시간은 약 49% 증가했다.

**Evidence / limitations:** 관찰연구이며 데이터는 2026년 3월까지다. Review 경과시간은 사람의 순수 작업시간이 아니고, issue 완료는 최종 사용자 가치의 완전한 지표가 아니다. Anthropic의 극단적 자동화 사례와 모순이라기보다 운영 환경이 다르다.

**Trend direction:** Growing but challenged. **Maturity:** Production measurement practice / causal interpretation debated.

## 1. Firmware Harness Engineering: build·flash·UART·HIL을 폐루프로

**Firmware interpretation:** `edit → cross-compile → static analysis → flash → UART capture → hardware test → evaluate → retry`를 agent workflow로 구성한다. 코드 생성 성공과 실제 보드 동작 성공을 분리한다.

**Practical workflow:** MCU·board revision을 먼저 식별하고 isolated worktree에서 수정한다. CMake/Ninja 또는 vendor toolchain으로 빌드한 뒤 flash는 승인된 board lease가 있을 때만 수행한다. UART/RTT 로그, 측정 결과, firmware hash를 CI artifact로 남긴다.

**Evidence / maturity:** Technically plausible architecture. University of Alberta의 2026 ECCE 프로젝트는 power electronics simulation과 real-time target을 agent로 반복 최적화한 제한적 공개 사례다. 범용 MCU 자동화의 성숙한 표준으로 보기는 어렵다.
