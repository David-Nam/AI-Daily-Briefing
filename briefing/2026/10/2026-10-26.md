# Session 2 — AI Development Trend Radar

### 1. Harness Security: Agent의 작업 권한과 검증 권한 분리

- **What it is:** 코드 생성 Agent와 이를 감시·평가하는 주체를 별도 신뢰 경계로 분리하는 설계다.
- **Problem / use:** Agent가 정책 파일, 로그 또는 테스트 판정을 수정하면 성공 판정이 자기보고가 된다. 실무에서는 실행 Sandbox, 읽기 전용 평가 기준, 별도 CI 권한, 불변 아티팩트로 해결한다.
- **Recent delta:** 10월 23일 OpenAI가 연구 훈련 환경 격리 개선을 공개했고, Codex 0.164.0과 Claude Code 2.1.309/310은 Sandbox·권한 검사 관련 수정을 다수 포함했다.
- **Evidence / limitations:** 실제 보안 사고와 제품 수정이 존재한다. 다만 특정 도구의 수정이 모든 우회 경로를 차단한다는 보장은 없다.
- **Trend direction / maturity:** Growing / Production security practice.
- **Sources:** [OpenAI 격리 설명](https://openai.com/index/securing-our-frontier-model-training-environment/) · [Codex Releases](https://github.com/openai/codex/releases) · [Claude Code Releases](https://github.com/anthropics/claude-code/releases)

### 2. Long-running Agent: Polling보다 이벤트 기반 Monitor와 취소 제어

- **What it is:** Agent가 긴 작업을 무한 폴링하는 대신 외부 이벤트를 감시하고 조건이 충족될 때 다음 작업을 진행하는 패턴이다.
- **Problem / use:** 불필요한 토큰 사용, 중복 작업, 종료 신호 이후 실행되는 Tool Call을 줄인다. 로그 감시, CI 완료 대기, 배포 후 이상 탐지에 적합하다.
- **Recent delta:** Claude Code 2.1.310은 Monitor와 클라우드 환경 호환성을 확대했고, Gemini CLI 10월 23일 nightly는 비대화형 취소 이후 Tool 실행을 막는 수정을 포함했다.
- **Evidence / limitations:** 릴리스 노트로 기능은 확인되지만 장시간 실행 시 누락 이벤트, 재시작 복원, 중복 알림은 별도 통합 테스트가 필요하다.
- **Trend direction / maturity:** Growing / Emerging practice.
- **Sources:** [Claude Code v2.1.310](https://github.com/anthropics/claude-code/releases/tag/v2.1.310) · [Gemini CLI Releases](https://github.com/google-gemini/gemini-cli/releases)

### 3. Eval-driven Development: 독립적인 실패 판정과 재현 가능한 테스트

- **What it is:** 모델이 생성한 결과를 별도의 정답 기준·테스트 Harness로 평가하고 실패 원인을 다음 반복에 반영하는 방식이다.

- **Evidence / limitations:** 벤치마크는 통제된 모델·태스크 조건의 결과이며 일반 제품의 절대 위험도로 해석하면 안 된다.

- **Sources:** [HarnessSecurity-Bench](https://arxiv.org/abs/2610.07639) · [Reuters 보안 분석](https://www.reuters.com/legal/litigation/ai-discovered-bugs-may-soon-trigger-fresh-disruptions-cyber-experts-say-2026-10-23/)

# Session 3 — AI for Firmware & Embedded Engineering

### 1. Firmware Harness를 교차 컴파일과 실제 보드 판정으로 확장

- **Firmware interpretation:** 범용 Agent의 edit → test 루프를 edit → cross-compile → flash → capture UART → HIL evaluate → retry로 구체화한다.
- **Practical workflow:** Agent는 격리된 Worktree에서 Embedded C/C++ 수정과 CMake 빌드를 수행한다. 독립 CI Runner가 빌드 아티팩트 해시를 검증한 뒤 지정 보드에 Flash하고 UART 로그와 테스트 결과를 수집한다.
- **Useful tools / interfaces:** CMake, arm-none-eabi-gcc, OpenOCD/ST-Link, pyserial, pytest, Zephyr Twister, GitHub Actions 또는 Gitea Runner.
- **Benefits:** 컴파일 성공과 장치 동작 성공을 분리해 자동 재현할 수 있다.
- **Limitations / risks:** 잘못된 Option Bytes·Erase·전압 설정은 복구 불가 상태나 하드웨어 손상을 만들 수 있다. Flash와 판정 서비스는 Agent 권한 밖에 둬야 한다.
- **Evidence / maturity:** 빌드/HIL 자체는 Production practice; Agent의 반복 수정까지 통합하는 부분은 Emerging practice.
- **Sources:** [Zephyr Twister](https://docs.zephyrproject.org/latest/develop/test/twister.html) · [OpenAI 격리 설계](https://openai.com/index/securing-our-frontier-model-training-environment/)

### 2. STM32·RTOS 개발에 읽기 전용 Datasheet Context와 권한 프로필 적용

- **Firmware interpretation:** Register/HAL 설정 변경은 Reference Manual, Errata, MCU Revision을 근거로 검토하고, 소스 수정과 장치 제어를 분리한다.
- **Practical workflow:** Agent 입력에는 문서 버전, 관련 레지스터 필드, Clock Tree, DMA·Cache 제약을 포함한다. 변경 후에는 정적 분석·빌드·Register Dump 비교를 수행하고, SWD 쓰기·Flash는 승인된 Wrapper만 허용한다.
- **Useful tools / interfaces:** ST Reference Manual/Errata, STM32CubeMX, CMake, clang-tidy, OpenOCD, GDB, UART trace.
- **Benefits:** 그럴듯하지만 MCU 리비전과 맞지 않는 생성 코드를 조기에 걸러낼 수 있다.
- **Limitations / risks:** PDF 검색 오류, HAL 버전 차이, 인터럽트 우선순위와 타이밍 경쟁 상태는 텍스트 검사만으로 검증되지 않는다.
- **Evidence / maturity:** 권한 분리·문서 버전 고정은 검증된 일반 엔지니어링 관행; Agent 통합은 설계 제안.
- **Sources:** [Codex Sandbox 개선](https://github.com/openai/codex/releases) · [Claude Code Sandbox 개선](https://github.com/anthropics/claude-code/releases)

### 3. BLE CoC·UART·SPI 프로토콜을 Agent가 아닌 독립 Oracle로 검증

- **Firmware interpretation:** Agent가 구현한 패킷 처리와 테스트 기대값을 동시에 변경하지 못하게 한다.
- **Practical workflow:** Python Host Test가 정상·손상 CRC·길이 불일치·재전송·연결 해제·Timeout 케이스를 송신한다. MCU 로그와 패킷 Capture를 독립 저장하고 Agent에는 요약된 실패 코드만 반환한다.
- **Useful tools / interfaces:** pytest, pyserial, BLE Sniffer, Wireshark, SWD/GDB, Fault Injection, 별도 Test Manifest.
- **Benefits:** 프로토콜 회귀를 재현하고 변경 영향 범위를 정량화할 수 있다.
- **Limitations / risks:** 무선 간섭과 비결정적 타이밍으로 Flaky Test가 생길 수 있다. Golden Trace는 제품·펌웨어 버전별로 관리해야 한다.
- **Evidence / maturity:** 프로토콜 회귀 검증은 Production practice; Agent 기반 수정 반복은 PoC 권장.
- **Sources:** [Zephyr Twister](https://docs.zephyrproject.org/latest/develop/test/twister.html) · [HarnessSecurity-Bench](https://arxiv.org/abs/2610.07639)

### 4. Edge AI Weight·Quantization 최적화는 정확도와 시스템 비용을 함께 평가

- **Firmware interpretation:** Agent가 Weight, Quantization, Layer 배치를 제안하더라도 정확도만 개선되면 성공이라는 판단을 피한다.
- **Practical workflow:** 고정 데이터셋과 칩 버전으로 Accuracy, p50/p95 Latency, Peak Memory, 전력, 온도별 실패율을 측정한다. Weight Program과 Firmware Flash는 서로 다른 명령·권한·Checksum으로 관리한다.
- **Useful tools / interfaces:** Python Eval Harness, 고정된 Calibration Dataset, Power Meter/DMM, UART Result Protocol, HIL Artifact Store.
- **Benefits:** 뉴로모픽·PIM 제약에서 실제 배포 가능한 Pareto 개선안을 선택할 수 있다.
- **Limitations / risks:** 테스트셋 과적합, 장치 간 편차, Flash 내구성, 전력 측정 노이즈가 결론을 왜곡할 수 있다.
- **Evidence / maturity:** 다중 지표 장치 검증은 Production practice; Agent 자율 최적화는 Experiment.
- **Sources:** [Zephyr 테스트 문서](https://docs.zephyrproject.org/latest/develop/test/twister.html) · [OpenAI Agents SDK Harness](https://openai.com/index/the-next-evolution-of-the-agents-sdk/)
