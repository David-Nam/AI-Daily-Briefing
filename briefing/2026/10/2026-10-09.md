# Session 2 — AI Development Trend Radar

## 1. Agent runtime이 identity·sandbox·audit·cost를 통합하는 control plane으로 진화

**What it is:** agent마다 identity와 least-privilege policy를 부여하고, tool execution을 sandbox에서 수행하며, action log와 token spending을 추적하는 운영 구조다.

**Problem it addresses:** multi-agent 시스템에서 누가 어떤 권한으로 무엇을 실행했는지 설명할 수 없으면 보안·비용·재현성 모두 취약해진다.

**How developers are using it:** Google은 Gemini agent의 identity, Agent Sandbox, Agent Gateway, audit trail, Smart Routing과 spend cap을 하나의 architecture로 설명했다. GitLab도 'governed software factory'를 통해 agent workflow와 CI/CD·security·artifact policy를 연결하는 방향을 발표했다.

**What changed recently:** 단일 agent prompt보다 조직 전체의 identity, execution policy와 cost routing을 관리하는 제품 구조가 10월 8일 주요 발표의 공통분모가 됐다.

**Evidence / limitations:** Google의 enterprise 사례와 수치는 vendor-reported다. 실제 운영에서 permission propagation, connector behavior, audit completeness를 독립 검증해야 한다.

**Trend direction:** **Growing** · **Maturity:** Emerging enterprise production architecture

**Sources:** [Google Cloud technical announcement](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026) · [GitLab coverage](https://itbrief.com.au/story/gitlab-unveils-governed-software-factory-tools-for-ai)

## 2. Fail-closed hook이 prompt-only guardrail의 한계를 보완

**What it is:** AI agent가 명령 실행 전 호출하는 hook이 실패·timeout·unexpected exit를 만나면 기본 허용 대신 작업을 차단하는 policy다.

**Problem it addresses:** hook이 실행되지 않았는데도 action이 통과하는 fail-open 동작은 보안 검사·품질 gate의 신뢰성을 무너뜨린다.

**How developers are using it:** Claude Code 2.1.295는 command/HTTP hook에 onFailure: block을 추가했다. 2.1.294는 지시문 형태의 prompt/agent hook이 차단해야 할 명령을 허용하던 문제를 수정했다.

**What changed recently:** policy 문장 자체보다 hook의 실행 실패 의미론과 강제성에 대한 수정이 실제 release에 포함됐다.

**Evidence / limitations:** release note는 동작 계약을 설명하지만 모든 hook 구현이 올바른 판단을 한다는 보장은 아니다. timeout 값, retry, human override를 별도로 설계해야 한다.

**Trend direction:** **Growing** · **Maturity:** Production feature

**Sources:** [Claude Code releases](https://github.com/anthropics/claude-code/releases) · [Claude Code hook behavior report](https://github.com/anthropics/claude-code/issues/100575)

## 3. AI-generated contribution 증가에 따라 repository-level quality gate 강화

**What it is:** agent가 만든 대량의 draft PR·작은 변경·자동 제안을 유지관리자가 처리할 수 있도록 rate limit, validation, review policy를 강화하는 방식이다.

**Problem it addresses:** 낮은 품질의 자동 기여가 reviewer 시간, CI minutes와 notification budget을 소모한다.

**How developers are using it:** GitHub는 10월 8일 draft PR도 사용자별 PR limit에 포함하도록 설정할 수 있게 했다. GitHub는 낮은 품질의 기여와 repository spam을 직접적인 배경으로 설명했다.

**What changed recently:** 'agent가 PR을 많이 만들 수 있다'는 생산성 지표보다 accepted PR, CI pass, reviewer burden을 측정해야 한다는 운영상의 신호가 강화됐다.

**Evidence / limitations:** GitHub의 설정은 spam 완화 기능이지 AI-generated PR을 자동 판별하거나 품질을 평가하는 도구는 아니다.

**Trend direction:** **Growing** · **Maturity:** Production repository control

**Sources:** [GitHub — draft PR limits](https://github.blog/changelog/2026-10-08-draft-pull-requests-count-toward-pull-request-limits/)

## 4. Worktree-per-agent가 CLI에 관리 기능으로 내장

**What it is:** 여러 coding agent가 하나의 repository를 공유하되 독립 Git worktree에서 수정·검증하도록 격리하는 패턴이다.

**Problem it addresses:** parallel agent가 같은 working tree를 수정하면 충돌, untracked file 오염, build artifact 혼선이 발생한다.

**How developers are using it:** Codex CLI 0.162.0은 신뢰된 local project에서 managed worktree 생성·목록 조회 도구를 feature flag 기반으로 추가했다.

**What changed recently:** worktree isolation이 외부 shell script 패턴을 넘어 coding-agent 자체의 관리 기능으로 들어왔다.

**Evidence / limitations:** Git worktree는 source 변경 충돌을 줄이지만 공유 build cache, serial port, debugger와 같은 외부 resource까지 격리하지 않는다.

**Trend direction:** **Growing** · **Maturity:** Emerging built-in feature

## 5. Long-running agent의 context compaction과 background completion은 여전히 취약점

**Evidence / limitations:** 개별 사용자 issue이며 widespread regression이나 재현 범위는 확정되지 않았다. 그러나 state-machine 기반 완료 판정과 explicit task result 확인의 필요성을 보여준다.

**Trend direction:** **Challenged / active engineering work** · **Maturity:** Practitioner reports

# Session 3 — AI for Firmware & Embedded Engineering

## 1. Firmware agent에 fail-closed hardware gate 적용

**Firmware interpretation:** Claude Code의 onFailure: block 같은 policy를 firmware flashing, option-byte 변경, OTP/eFuse programming, power cycling 등 물리적 action 앞에 배치한다.

**Practical workflow:** edit → cross-compile → static analysis → 승인된 flash target 검증 → programmer 실행 → UART/RTT capture → HIL assertion. Hook 실패나 target ID 불일치 시 flash를 실행하지 않는다.

**Useful tools / interfaces:** Claude Code hooks, OpenOCD, STM32CubeProgrammer CLI, J-Link, udev device identity, CI approval gate.

**Benefits:** agent가 잘못된 board에 firmware를 기록하거나 안전 검사 실패를 무시하는 위험을 낮출 수 있다.

**Limitations / risks:** prompt 기반 hook만으로는 충분하지 않다. device identity 확인과 write permission enforcement를 tool wrapper/OS layer에도 둬야 한다.

**Evidence / maturity:** **Production hook feature + proposed embedded integration; not a proven universal HIL solution**

**Sources:** [Claude Code release notes](https://github.com/anthropics/claude-code/releases)

## 2. Parallel firmware agent에는 Git worktree 외에 hardware resource lease가 필요

**Firmware interpretation:** Codex의 managed worktree는 agent별 source tree를 격리하지만, 여러 agent가 하나의 SWD probe, UART port, board power relay를 동시에 사용하면 실험이 깨진다.

**Practical workflow:** agent A/B는 각 worktree에서 병렬 build하고, HIL queue가 board_id·probe_serial·port를 exclusive lease로 예약한 뒤 flash/test를 직렬화한다. 결과에는 commit SHA, binary hash, board revision, toolchain version, test timestamp를 남긴다.

**Useful tools / interfaces:** Git worktree, CMake/Ninja, pytest, serial logger, OpenOCD/J-Link, board farm reservation service.

**Benefits:** software parallelism은 유지하면서 hardware nondeterminism과 test interference를 줄일 수 있다.

**Limitations / risks:** Git isolation만으로 hardware isolation은 보장되지 않는다. physical board 상태 복원과 timeout/recovery가 필수다.

**Evidence / maturity:** **Codex worktree feature confirmed; hardware lease is engineering recommendation**

**Sources:** [Codex CLI releases](https://github.com/openai/codex/releases)

## 3. Agent identity·audit 설계를 MCU debug tool gateway에 적용

**Firmware interpretation:** Google이 제시한 agent별 identity와 action audit를 embedded lab의 SWD/JTAG/UART tool server에 적용할 수 있다.

**Practical workflow:** read-only log agent와 write-capable flash agent를 다른 service identity로 분리한다. tool call마다 requester, target board, operation, binary SHA, approval, result를 기록한다.

**Useful tools / interfaces:** OAuth/service account, MCP gateway, serial console, debug probe wrapper, immutable audit log.

**Benefits:** 어떤 agent가 어떤 board에서 어떤 firmware를 실행했는지 추적할 수 있고, 개발/생산 장비의 권한도 분리하기 쉽다.

**Limitations / risks:** Google Cloud의 Agent Gateway가 물리 debug probe를 직접 통제한다는 뜻은 아니다. hardware-specific gateway는 별도로 구현해야 한다.

**Evidence / maturity:** **Enterprise agent architecture confirmed; firmware adaptation proposed**

**Sources:** [Google Cloud — identity and Agent Gateway](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026)

## 4. Gemini CLI sandbox·YOLO 회귀 보고는 unattended HIL의 위험 신호

**Firmware interpretation:** 자동승인 agent로 build/flash/test loop를 돌릴 때 CLI의 permission parser나 sandbox policy가 바뀌면 정상 명령이 막히거나 예상치 못한 승인이 필요할 수 있다.

**Practical workflow:** production HIL에 CLI를 올리기 전에 버전을 pin하고, safe git diff/build, denied flash, network-disabled mode를 포함한 policy regression suite를 실행한다.

**Useful tools / interfaces:** Gemini CLI, sandbox.toml, CI smoke test, command allowlist, isolated test board.

**Benefits:** agent runtime 업데이트가 firmware test infrastructure를 갑자기 중단시키는 일을 줄인다.

**Limitations / risks:** GitHub issue는 사용자 보고이며 재현 범위가 검증되지 않았다. YOLO mode는 destructive hardware operation에 사용하지 않는 편이 안전하다.

**Evidence / maturity:** **Practitioner bug reports + recommended operational mitigation**

**Sources:** [Gemini CLI sandbox policy issue](https://github.com/google-gemini/gemini-cli/issues/29686) · [YOLO warning regression](https://github.com/google-gemini/gemini-cli/issues/29676)
