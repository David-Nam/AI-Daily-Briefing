# Session 2 — AI Development Trend Radar

## 1. Long-running agent: Active Memory와 지속 실행 능력의 경쟁

**What it is:** 여러 세션에 걸친 사용자·프로젝트 문맥을 선택적으로 보존하고, 막힌 작업을 다른 경로로 계속 해결하는 agent 설계다. **Problem:** 단순 context window 확장만으로는 장기 작업의 관련 정보 검색, 목표 유지, 완료 판정을 해결하지 못한다.

**How developers use it:** 명시적 task state, 검색 가능한 memory, 작업 단계별 checkpoint, acceptance test를 결합한다. Meta는 Active Memory·Active Focus 및 SWE-Marathon·FocusBench 결과를 공개했다.

**Recent delta / Evidence:** Muse Wonder 발표로 memory와 long-running coding이 제품의 핵심 기능으로 부상했다. 다만 비교 benchmark는 Meta의 공개 평가이고, 실제 팀의 multi-day 유지보수 성공률을 독립적으로 보장하지 않는다.

**Trend direction:** Growing. **Maturity:** Emerging production feature / Evaluation still developing.

**Sources:** [Meta technical overview](https://research.meta.ai/blog/muse-wonder?utm_source=chatgpt.com) · [TechCrunch analysis](https://techcrunch.com/2026/10/12/meta-releases-its-first-frontier-model-muse-wonder/?utm_source=chatgpt.com)

## 2. Permission state와 hook의 fail-closed 동작

**What it is:** agent가 명령·브라우저·MCP tool을 호출하기 전에 정책을 평가하고, 검사 실패나 세션 재개 중에도 권한이 확대되지 않게 하는 실행 구조다. **Problem:** 모델의 선의나 지시문만으로는 위험한 side effect를 차단할 수 없다.

**How developers use it:** PreToolUse hook, tool allowlist, read-only credential, sandbox, deny-by-default action, resume regression test를 사용한다.

**Recent delta / Evidence:** Claude Code 2.1.295/2.1.296의 onFailure block 및 managed hook·disabled MCP 수정이 이어졌다. 이번 24시간의 신규 릴리스는 확인되지 않았지만, 직전 릴리스의 permission 관련 회귀는 계속 검증할 가치가 있다.

**Trend direction:** Growing / Reliability challenged. **Maturity:** Production security practice with tool-specific gaps.

**Sources:** [Claude Code releases](https://github.com/anthropics/claude-code/releases?utm_source=chatgpt.com) · [Anthropic incident disclosure](https://www.anthropic.com/news/investigating-unintended-model-actions?utm_source=chatgpt.com)

## 3. Agent provenance: commit 작성자와 실제 push 주체를 구분

**What it is:** AI agent가 만든 commit의 author/committer 문자열과 실제 인증된 push 계정을 분리해 추적하는 감사 구조다. **Problem:** Git commit metadata는 임의 문자열이므로 권한이 낮은 계정이 신뢰된 maintainer처럼 보이게 만들 수 있다.

**How developers use it:** repository ruleset, verified pusher identity, CI artifact attestation, agent run ID와 commit SHA의 연결을 고려한다.

**Recent delta / Evidence:** GitHub는 10월 12일 Enterprise 대상 limited public preview로 authenticated pusher attribution과 'Committer must match pusher' 규칙을 발표했다. 일반 GitHub 사용자에게 즉시 제공되는 기능은 아니다. [The GitHub Blog](https://github.blog/changelog/2026-10-12-push-attribution-public-preview)

**Trend direction:** Growing. **Maturity:** Limited enterprise preview / General provenance principle mature.

**Sources:** [GitHub Changelog — push attribution](https://github.blog/changelog/2026-10-12-push-attribution-public-preview/?utm_source=chatgpt.com)

## 4. Eval-driven development: 모델 benchmark보다 작업별 재현 테스트

**What it is:** agent의 실제 성공 여부를 요구사항·테스트·비용·실행 시간·side effect로 평가하는 개발 방식이다. **Problem:** vendor benchmark 점수는 실제 저장소의 규칙·툴체인·권한 경계를 대변하지 못한다.

**How developers use it:** 동일 issue에 대해 여러 모델을 격리된 worktree에서 실행하고, unit/integration test와 reviewer 판단을 비교한다. 장기 작업에서는 중단·재시작·컨텍스트 압축 후 상태 복원을 추가 평가한다.
