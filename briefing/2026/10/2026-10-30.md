# Session 3 — AI for Firmware & Embedded Engineering

### 1. HIL Harness: edit → build → flash → UART → assert → retry

- **Firmware interpretation:** 코딩 agent의 test-feedback loop를 실제 보드·전원·시리얼·플래시 도구에 연결한다.
- **Practical workflow:** 독립 worktree에서 수정하고 cross-compile한 뒤, 예약한 보드에서만 flash, UART log 수집, boot marker·timeout·프로토콜 응답을 검사한다. 실패 시 로그와 재현 절차를 agent에 돌려준다.
- **Tools / interfaces:** labgrid, labgrid-mcp, SWD/JTAG, OpenOCD, UART, pytest.
- **Benefits:** 반복적인 bring-up·회귀 검증의 수동 조작을 줄인다.
- **Risks:** flash 및 전원 제어는 장비 상태를 바꾸므로 기본 read-only, 명시적 장비 예약, 이미지 검증, flash 별도 승인, 실패 시 전원 복구가 필요하다.
- **Evidence / maturity:** labgrid-mcp는 47개 tool을 노출하는 실제 공개 프로젝트지만, 대규모 생산 환경 검증은 확인되지 않았다. Emerging / 실험적 통합.
- **Sources:** [labgrid-mcp](https://github.com/onurcelep/labgrid-mcp)

### 2. STM32·ThreadX 펌웨어에 적용할 Eval-driven Development

- **Firmware interpretation:** AI가 만든 driver·RTOS 변경을 컴파일 성공으로만 평가하지 않고 latency, stack high-water mark, heap 사용량, watchdog, 재연결률까지 검증한다.
- **Practical workflow:** 요구사항을 테스트로 고정하고 host-side unit test → cross-compile → static analysis → HIL 순서로 gate를 통과시킨다. BLE CoC 등 통신 코드는 packet loss·disconnect·reconnect·buffer exhaustion을 fault injection으로 반복한다.
- **Tools / interfaces:** CMake/CTest, Unity 또는 Ceedling, clang-tidy, ThreadX trace, pyserial, logic analyzer.
- **Benefits:** agent의 잘못된 HAL 호출이나 타이밍 회귀를 실제 관측값으로 걸러낸다.
- **Risks:** 테스트 oracle이 약하면 잘못된 동작을 통과시킨다. 하드웨어 비결정성과 장비 간 편차를 기록해야 한다.
- **Evidence / maturity:** 기존 검증 도구는 Production practice, agent를 닫힌 루프로 연결하는 부분은 제안 workflow다.
- **Sources:** [Microsoft harness](https://blogs.microsoft.com/blog/2026/10/28/introducing-the-microsoft-copilot-harness-unlocking-the-potential-of-truly-multi-model-agentic-work/) · [labgrid-mcp](https://github.com/onurcelep/labgrid-mcp)

### 3. Datasheet 기반 agent에 권한 경계와 증거 연결

- **Firmware interpretation:** PDF/reference manual에서 register 정의를 검색해 driver를 생성하더라도, 원문 근거와 실측 검증을 분리해 관리한다.
- **Practical workflow:** register address, bit field, reset value, errata와 silicon revision을 추출해 변경 제안에 출처를 붙이고, read-only register dump와 unit test로 확인한 뒤 위험한 쓰기·flash는 사람 승인으로 제한한다.
- **Tools / interfaces:** datasheet parser, CMSIS-SVD, OpenOCD, MCP read-only adapter, CI.
- **Benefits:** register-level 추측과 문서 버전 혼동을 줄일 수 있다.
- **Risks:** LLM이 존재하지 않는 register를 만들거나 reserved bit를 쓰면 실제 하드웨어 손상·오동작으로 이어질 수 있다.
- **Evidence / maturity:** 설계 제안이며 오늘 신규 양산 사례를 확인한 것은 아니다. Experiment.
- **Sources:** [labgrid-mcp 권한 설계](https://github.com/onurcelep/labgrid-mcp) · [Google Carbon 발표](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/)
