# Session 3 — AI for Firmware & Embedded Engineering

## 1. Firmware Harness가 실제 `flash → observe → verify` loop로 구체화

**Firmware interpretation:** 일반 Harness Engineering을 MCU에 적용하면 `edit → cross-compile → flash → UART/RTT/SWD observation → evaluator → retry`가 된다.

`PIO Agent/platformio-mcp`는 `agent_build_diagnose`, `agent_safe_pin_audit`, `agent_flash_monitor_verify` 등을 제공한다. flash 후 serial output에서 `BOOT_OK` 같은 assertion을 확인하고 crash/brownout/WDT pattern을 reject할 수 있다.

**Practical workflow:** source 수정 → PlatformIO build → target resolve → flash → bounded serial monitor → expected/reject pattern 평가 → JSON report → agent retry.

**Benefits:** compile 성공과 실제 target 정상 동작을 분리해 평가할 수 있다.

**Limitations / risks:** serial string만으로 physical correctness를 증명할 수 없다. ADC, timing, current, BLE RF, SPI waveform 등은 별도 instrumentation이 필요하다.

**Evidence / maturity:** 실제 공개 구현이 존재하지만 3.1.0은 development 상태이고 published installation은 3.0.0이라고 repository가 명시한다. Emerging experiment.

**Sources:** https://github.com/jl-codes/platformio-mcp

## 2. ELF + SVD + probe가 Firmware Context/Observation의 핵심 조합

`openocd-mcp`는 ELF/DWARF symbol과 CMSIS-SVD를 이용해 raw address 대신 변수와 peripheral register를 이름으로 읽는다. ST-Link, J-Link, CMSIS-DAP 등 OpenOCD-supported probe를 사용할 수 있다.

`jlink-mcp`도 ELF symbol, RTT, Cortex-M fault decode를 결합하며 실제 nRF52840-DK HIL test를 통해 symbolized backtrace와 debug workflow를 검증한다고 설명한다.

**Firmware interpretation:** datasheet 전체를 context에 넣는 것보다 `source + ELF/DWARF + SVD + live target observation`을 연결하는 편이 hallucination을 줄이는 데 더 직접적이다.

**Benefits:** agent가 “SPI clock이 켜져 있을 것”이라고 추측하지 않고 RCC register를 실제로 읽어 확인할 수 있다.

**Limitations / risks:** probe/tool success가 board-level correctness를 보장하지 않는다. 잘못된 memory write, flash erase, option-byte 변경은 실제 장치를 손상시키거나 복구 비용을 만들 수 있다.

**Evidence / maturity:** open-source early implementation; jlink-mcp는 real-hardware test를 공개하지만 ecosystem 전체의 production maturity를 의미하지 않는다.

**Sources:** https://github.com/microhenrio/openocd-mcp , https://github.com/Klievan/jlink-mcp/

## 3. Firmware agent permission은 operation risk별로 분리해야 함

`openocd-mcp`는 read-only mode, memory-write gate, flash gate, erase opt-in, allowed path, image-size limit 등을 제공한다.

Firmware에서는 일반 filesystem sandbox보다 다음과 같은 hardware-aware policy가 필요하다.

| Operation | 권장 기본 정책 |
|---|---|
| ELF/SVD 조회 | Auto |
| register/memory read | Auto |
| UART/RTT capture | Auto |
| halt/resume/breakpoint | Allow with scope |
| normal flash | Restricted |
| arbitrary memory write | Confirm |
| sector/mass erase | Explicit confirm |
| option bytes / OTP / eFuse | Explicit confirm or deny |

**Maturity:** Emerging practice.
