# Session 3 — AI for Firmware & Embedded Engineering

## 실험 제안: 재개 가능한 HIL 작업 상태와 독립 결과 확인

**아래는 이번 릴리스의 Firmware 적용 해석이며, 검증된 신규 도입 사례가 아닙니다.**

- **Firmware 해석:** build → flash → UART 수집 → 테스트 → 판정 과정에서 에이전트가 중단되어도 어느 단계까지 완료했는지 복원해야 합니다.
- **실용 흐름:** 단계별 실행 ID, Git commit, 빌드 산출물 hash, 보드 ID, 테스트 시작·종료, 판정 결과를 기록합니다. 재개 시 보드 상태를 다시 읽고 다음 단계를 결정합니다.
- **도구 / 인터페이스:** 기존 cross-compiler, flashing CLI, UART logger, 테스트 runner를 각각 분리된 호출로 연결하는 구성을 시험할 수 있습니다.
- **효과 — 가설:** 상태 기록과 재읽기 검증이 있으면 완료 오인과 무조건적인 재실행을 줄일 수 있습니다.
- **한계:** 호스트의 원자적 파일 저장은 칩 Flash의 완료나 보드 정상 상태를 보장하지 않습니다. 전원 중단, 통신 timeout, 보드별 차이, 잘못된 테스트 판정은 별도 처리해야 합니다.
- **검증 항목:** flash 이후 상태 기록 전에 중단, UART 수집 중 disconnect, 테스트 완료 후 결과 저장 실패를 각각 주입해 확인합니다.
- **근거 / 성숙도:** Gemini CLI 복구 구현을 참고한 실험 제안. Firmware HIL에서의 효과는 미검증.
- **출처:** [상태 저장·복구 구현 PR](https://github.com/google-gemini/gemini-cli/pull/29558).
