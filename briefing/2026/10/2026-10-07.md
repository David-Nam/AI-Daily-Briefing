## 1. Eval-driven Agent Engineering: “작업 완료”를 세부 criteria로 정의

**What it is:** agent가 task를 끝냈는지를 “출력이 그럴듯한가”가 아니라 명시적인 requirement/evaluator 집합으로 판정하는 방식이다.

**Problem it addresses:** long-running GUI/tool agent는 중간 step을 성공해도 최종 workflow constraint를 놓치기 쉽다.

**How developers are using it:** OpenAI와 Ironclad의 연구에서는 11개 contracting task를 만들고 task별로 8~50개의 criteria를 정의했다. agent는 hosted Ironclad environment에서 실제 multi-step workflow를 수행하고 최종 상태가 criteria를 만족하는지 평가받았다. citeturn172653search0

**Evidence / limitations:** OpenAI는 GPT-6 Astra가 해당 11개 research task에서 GPT-5.6 Sol보다 평균 score가 높고 simulated attempt time이 짧았다고 보고했지만, 이는 제한된 vendor research evaluation이며 customer productivity를 직접 측정한 결과가 아니다. citeturn172653search0

**Trend direction:** **Growing**

## 2. Permission Engineering: agent identity와 operation risk를 함께 본다

**What it is:** permission을 단순한 tool allow/deny가 아니라 main agent/subagent identity, operation type, organization policy와 결합해 판단하는 방식이다.

**Problem it addresses:** multi-agent 환경에서는 동일한 shell/MCP tool이라도 어떤 agent가 어떤 목적에서 호출하는지에 따라 risk가 다르다.

**What changed recently:** Claude Code v2.1.290은 plugin hook의 `tool.check` event에 `agentId`를 추가해 subagent permission check를 main session과 구분할 수 있게 했다. v2.1.291은 2.1.290에서 cloud session의 permission prompt 응답이 유실되는 regression을 바로 수정했다. citeturn720853search2

**Evidence / limitations:** shipping product에 들어간 runtime primitive라는 점에서 강한 signal이다. 반면 permission graph가 복잡해지면 configuration error가 새로운 failure mode가 될 수 있다.

**Trend direction:** **Growing**

**Maturity:** **Production practice**

**Sources:** urlClaude Code releaseshttps://github.com/anthropics/claude-code/releases

## 3. Observability가 agent의 interactive tool surface로 이동

**What it is:** agent가 logs/metrics/traces를 단순 context로 읽는 것을 넘어 query → hypothesis → verification → proposed action loop를 수행한다.

**How developers are using it:** Coralogix는 10월 6일 MCP + CLI workflow에서 agent가 telemetry를 query하고 operational question을 조사하며, human judgment와 agent-driven investigation을 결합하는 방식을 시연했다. citeturn545165search2

## 2. Firmware에서는 Context Engineering보다 `Observation Engineering`이 더 중요해진다

**Firmware interpretation:** source와 datasheet만 context로 주는 대신 실제 target register, fault state, RTT/UART log를 agent가 직접 읽게 한다.

`openocd-mcp`는 OpenOCD를 통해 flash, execution control, variable/peripheral register access를 제공하고 ELF/SVD 기반의 named access를 지원한다. `jlink-mcp`는 J-Link/OpenOCD/Black Magic backend를 이용해 register/memory, RTT, Cortex-M fault decode, breakpoint, GDB server 등을 제공한다. citeturn758398search0turn758398search1

**Practical workflow:** `edit → cross-compile → flash → register/RTT/UART observation → deterministic evaluator → retry`.

**Useful tools / interfaces:** ELF/DWARF, CMSIS-SVD, OpenOCD, ST-Link/J-Link/CMSIS-DAP, RTT/UART.

**Benefits:** agent가 “SPI clock이 enable됐을 것”이라고 추측하지 않고 실제 RCC bit를 확인할 수 있다.

**Limitations / risks:** digital probe evidence만으로 analog/RF/power/timing correctness를 증명할 수 없다. logic analyzer, oscilloscope, programmable PSU 등 별도 instrumentation이 필요하다.

**Evidence / maturity:** **Open-source early implementation / real-hardware experiment**

**Sources:** urlopenocd-mcphttps://github.com/microhenrio/openocd-mcp · urljlink-mcphttps://github.com/Klievan/jlink-mcp/

## 3. Ironclad식 evaluator를 firmware HIL로 옮기면 무엇이 달라지는가

**Firmware interpretation:** Session 2의 multi-criteria evaluator를 firmware에 적용하면 build success 하나가 아니라 실제 hardware acceptance criteria를 명시할 수 있다.

예:

`build == PASS`  
`flash == PASS`  
`BOOT_OK observed within 2 s`  
`no HardFault / WDT reset`  
`SPI ID register == expected`  
`UART protocol test == PASS`  
`current consumption < threshold`

**Practical workflow:** agent가 코드를 수정한 뒤 build/flash를 수행하고, serial/probe/test fixture에서 각 criterion을 수집해 pass/fail을 판정한다.

**Benefits:** “코드를 만들었다”와 “target이 요구사항대로 동작한다”를 분리할 수 있다.

**Limitations / risks:** weak oracle가 가장 큰 문제다. LED가 켜졌다는 사실만으로 전체 기능이 정상이라고 볼 수 없고, destructive flash/erase/option-byte operation에는 별도의 approval boundary가 필요하다.

**Evidence / maturity:** **Technically plausible translation of an emerging agent-evaluation pattern; firmware-specific production evidence is still limited.** citeturn172653search0turn758398search0

## 4. 권장 Firmware Agent Permission Baseline

| Operation | Recommended default |
|---|---|
| source / ELF / SVD lookup | Auto |
| register / memory read | Auto |
| UART / RTT capture | Auto |
| halt / resume / breakpoint | Scoped |
| normal flash | Restricted |
| arbitrary memory write | Confirm |
| sector / mass erase | Explicit confirm |
| option bytes / OTP / eFuse | Explicit confirm or deny |

`openocd-mcp`도 read-only master switch, memory write, flash, erase, raw-command gate와 flash path/size 제한을 별도로 제공한다. 중요한 점은 **“flash succeeded”와 “device remains safe”는 서로 다른 assertion**이라는 것이다. citeturn758398search0
