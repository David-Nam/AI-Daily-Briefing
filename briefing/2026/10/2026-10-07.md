# Session 2 — AI Development Trend Radar

## 1. Execution Contract가 prompt보다 중요해짐

**What it is:** Agent에게 목표만 주는 대신 실행 stage, tool boundary, permission, expected artifact, evaluator, checkpoint를 명시하는 방식이다.

**Problem it addresses:** long-running agent의 비결정성, debugging 난이도, destructive action, cost attribution 문제.

**How developers are using it:** plan → implement → test → review를 명시적인 workflow로 만들고, 판단이 필요한 부분에만 agent를 사용한다.

**What changed recently:** GitHub Copilot의 Dynamic Workflows 같은 code-defined orchestration과 observability vendor의 MCP/CLI agent interface가 이 방향을 강화하고 있다.

**Evidence / limitations:** vendor tooling은 빠르게 늘지만 independent production ROI 데이터는 아직 부족하다. orchestration layer 자체가 새로운 complexity가 될 수 있다.

**Trend direction:** growing
**Maturity:** Emerging practice

**Sources:** https://github.blog/changelog/2026-10-01-dynamic-workflows-in-copilot-cli-and-the-copilot-app/
https://coralogix.com/events/from-prompt-to-production-us/

## 2. Observability가 agent tool surface로 이동

Agent가 telemetry를 읽고 incident hypothesis를 만들고 검증하는 흐름이 늘고 있다.

`query telemetry → hypothesis → verify → proposed action`

중요한 변화는 observability가 단순 context source가 아니라 agent의 interactive tool이 된다는 점이다.

**Limitations:** production telemetry에는 customer data와 secrets가 포함될 수 있다. remediation action까지 허용한다면 read-only default, scoped credentials, approval, audit log가 필요하다.

**Trend direction:** growing
**Maturity:** Emerging practice

## 3. Agent runtime security가 software supply-chain 문제로 확장

MCP servers, skills, hooks, AGENTS.md/CLAUDE.md와 permission 설정은 사실상 새로운 dependency layer다. 따라서 package dependency와 마찬가지로 version pinning, provenance, permission review, secret boundary가 필요하다.

**Trend direction:** growing
**Maturity:** Emerging practice

# Session 3 — AI for Firmware & Embedded Engineering

## 1. Cortex-M debugging을 agent tool로 노출

ProbeCodex는 OpenOCD/PyOCD/J-Link를 통해 MCP-compatible coding agent가 Cortex-M target의 flash/debug/trace 정보를 사용할 수 있게 하는 beta 도구다.

**Firmware interpretation:** source generation만 agent에 맡기는 것이 아니라 실제 target state를 observation loop에 넣는다.

**Practical workflow:**
`edit → cross-compile → flash → register/RTT/UART observation → deterministic evaluator → retry`

**Useful tools/interfaces:** ELF/DWARF, CMSIS-SVD, OpenOCD, PyOCD, J-Link, RTT, UART.

**Benefits:** agent가 peripheral state나 fault 원인을 추측하지 않고 실제 register/fault/trace evidence를 수집할 수 있다.

**Limitations/risks:** register와 RTT만으로 analog, RF, timing, current consumption을 검증할 수 없다. flash/erase/memory-write는 destructive operation이므로 permission gate가 필요하다.

**Evidence/maturity:** public beta / Emerging experiment

**Sources:** https://www.probecodex.com/

## 2. Firmware에서는 Context Engineering + Observation Engineering

Firmware agent에 필요한 context는 source와 datasheet만이 아니다.

`Source + ELF/DWARF + CMSIS-SVD + live probe + UART/RTT + test fixture`

가 함께 있어야 한다. 특히 MCU에서는 실제 hardware state가 가장 강한 evaluator가 된다.

권장 permission baseline:

| Operation | Default |
|---|---|
| source / ELF / SVD lookup | Auto |
| register / memory read | Auto |
| UART / RTT capture | Auto |
| halt / resume / breakpoint | Scoped |
| normal flash | Restricted |
| arbitrary memory write | Confirm |
| mass erase | Explicit confirm |
| option bytes / OTP / eFuse | Explicit confirm or deny |
