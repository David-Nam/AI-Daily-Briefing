# Session 2 — AI Development Trend Radar

## 1. Harness가 새로운 software supply chain이 됨

**What it is:** AGENTS.md/CLAUDE.md, skills, hooks, MCP servers, subagents, permission declarations가 coding agent의 실행환경을 구성하는 별도 dependency layer가 되는 현상이다.

**Problem it addresses:** reusable agent capability를 repository와 team 간 공유할 수 있지만, 동시에 dependency provenance와 permission 문제가 생긴다.

**What changed recently:** 3,171 public GitHub repositories를 분석한 최근 연구는 검사한 setup 중 9.8%가 version-unpinned MCP server를 설치하고, 일부는 broad shell execution을 pre-approve하는 등 harness configuration 자체에 security defect가 있음을 보고했다.

**Evidence / limitations:** academic preprint이며 corpus와 rule definition에 의존한다. credential exfiltration path 자체는 확인되지 않았다. 따라서 수치를 전체 ecosystem에 그대로 일반화하면 안 된다.

**Trend direction:** growing, with security hardening becoming necessary

**Maturity:** Emerging practice

**Sources:**
- https://arxiv.org/abs/2609.07360

## 2. Agent infrastructure가 desktop harness에서 shared production infrastructure로 이동

MCP Dev Summit과 AGNTCon/MCPCon의 program을 보면 관심사가 MCP 연결 자체에서 identity/permission, observability, eval, interoperability, multi-agent coordination으로 이동하고 있다. 이는 `model + tools`만으로는 production agent가 되지 않는다는 신호다.

**Practical pattern:** `task → isolated runtime → scoped tools → telemetry → evaluator → checkpoint/review`.

**Limitations:** conference agenda는 adoption proof가 아니다. 실제 production ROI와 failure rate에 대한 독립 데이터는 여전히 부족하다.

**Trend direction:** growing

**Maturity:** Emerging → Production practice

**Sources:**
- https://events.linuxfoundation.org/mcp-dev-summit-toronto/
- https://events.linuxfoundation.org/agntcon-mcpcon-north-america/

## 3. Observability가 agent tool surface로 들어감

Coralogix 등 observability vendor가 MCP/CLI를 통해 agent가 telemetry를 직접 query하고 incident를 조사하는 workflow를 전면에 내세우고 있다.

핵심은 agent가 log를 context로 받는 것을 넘어 `query telemetry → hypothesis → verify → action` loop를 수행하는 것이다.

**Risk:** production observability access에는 secret, customer data, destructive remediation action이 포함될 수 있으므로 read-only default와 action approval이 중요하다.

**Trend direction:** growing

**Maturity:** Emerging practice

## 1. AMD Ross — Embedded development용 agentic stack이 vendor product로 등장

**Limitations/risks:** 현재 효율 향상 주장은 주로 AMD의 official claim이다. independent production benchmark가 필요하며 AMD ecosystem에 강하게 결합된다.

**Evidence/maturity:** Official product; early adoption evidence.

## 2. Cortex-M agent debugging — `observation`을 reasoning보다 우선

ProbeCodex와 `jlink-mcp`는 OpenOCD/PyOCD/J-Link 등을 통해 register, memory, RTT, fault state, execution control을 MCP tool로 제공한다.

**Practical workflow:** `edit → cross-compile → flash → read live state → capture RTT/UART → deterministic check → retry`.

**Benefits:** agent가 “clock이 enable됐을 것”이라고 추측하는 대신 RCC/register를 직접 확인할 수 있다.

**Limitations:** register/debug evidence는 analog/RF/power/timing correctness를 보장하지 않는다. oscilloscope, logic analyzer, programmable PSU 같은 instrumentation을 추가해야 완전한 HIL loop에 가까워진다.

**Maturity:** Emerging experiment.

**Sources:**
- https://probecodex.com/
- https://github.com/Klievan/jlink-mcp/

## 3. Firmware agent permission model

Firmware에서는 일반 filesystem sandbox보다 operation risk를 기준으로 permission을 나누는 것이 중요하다.

| Operation | Recommended default |
|---|---|
| source / ELF / SVD lookup | Auto |
| register / memory read | Auto |
| UART / RTT capture | Auto |
| halt / resume / breakpoint | Scoped |
| normal flash | Restricted |
| arbitrary memory write | Confirm |
| sector / mass erase | Explicit confirm |
| option bytes / OTP / eFuse | Explicit confirm or deny |

이 구조는 Harness Engineering의 firmware 버전을 만들 때 가장 먼저 설계할 부분이다.
