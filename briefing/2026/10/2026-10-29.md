# Session 3 — AI for Firmware & Embedded Engineering

### 1. GitHub Agentic Workflows를 Firmware CI에 적용
- **Firmware interpretation:** Agent가 Build Failure를 분석하고 수정 후보를 생성하되 Flash·Merge는 별도 승인 경계로 분리한다.
- **Practical workflow:** PR 생성 → ARM Cross-compile → Static Analysis → Agent CI Log 분석 → 수정 PR 제안 → 사람 검토 → 전용 Runner에서 Flash·UART Test → 독립 Test Oracle 평가.
- **Useful tools / interfaces:** GitHub Actions/Agentic Workflows, CMake, arm-none-eabi-gcc, clang-tidy, OpenOCD, pyserial, pytest.
- **Benefits:** Build Log 분류와 Regression Test 초안 생성을 자동화하고 HIL 장치 사용을 통제할 수 있다.
- **Limitations / risks:** Agent가 Test Oracle을 함께 수정하거나 잘못된 Flash 대상에 접근하지 못하게 권한 분리·Board ID 검증이 필요하다.
- **Evidence / maturity:** GitHub GA 기능 확인; MCU HIL 적용은 설계 제안.
- **Sources:** [GitHub GA](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/) · [Zephyr Twister](https://docs.zephyrproject.org/latest/develop/test/twister.html)

### 2. STM32WBA ThreadX·BLE CoC용 승인형 Agent Harness
- **Firmware interpretation:** Agent의 코드 수정과 실제 BLE 무선 시험을 분리하고, Test Fixture를 고정한다.
- **Practical workflow:** BLE CoC RX/TX 변경 → 빌드 → CRC·Fragmentation·Disconnect·Timeout 테스트 생성 → ST-Link Flash 승인 → UART Trace·Sniffer Log 수집 → Golden Packet과 비교.
- **Useful tools / interfaces:** STM32Cube, ThreadX, ST-Link, BLE Sniffer, pyserial, pytest, Gitea Runner.
- **Benefits:** Timing·Buffer Regression을 소스 리뷰만으로 놓치는 문제를 줄인다.
- **Limitations / risks:** Radio Interference·Clock Drift·전원 상태에 따른 Flaky Test, Option Bytes 변경과 Mass Erase 위험이 있다.
- **Evidence / maturity:** HIL은 검증된 기법; Agent 자동화 결합은 팀별 PoC 필요.
