# Session 2 — AI Development Trend Radar

## 1. Agent sandboxing이 optional guardrail에서 execution baseline으로 이동

**What it is:** agent가 shell, filesystem, network, credentials, MCP server를 사용할 때 OS/runtime이 명시적 policy로 접근범위를 제한하는 방식이다.

**Problem it addresses:** coding agent가 자율적으로 command를 실행할수록 prompt-level permission만으로는 credential leakage, unintended network access, destructive filesystem action을 충분히 통제하기 어렵다.

**How developers are using it:** GitHub Copilot local sandboxing은 CLI, Copilot app, VS Code Agent Host에서 GA가 됐으며 Windows/macOS/Linux에 공통 policy를 적용한다. filesystem path, internet/local network, Git/GitHub credential, local MCP 접근을 제한할 수 있고 enterprise admin이 개발자가 완화할 수 없는 policy도 설정할 수 있다.

**What changed recently:** 10월 7일 GA 전환과 함께 sandboxing이 experimental feature가 아니라 일반 agent workflow의 production control로 자리잡았다.

**Evidence / limitations:** tool isolation은 model alignment와 별개의 layer라서 매우 유용하지만, USB device, debugger, cloud credential 등 모든 external capability를 자동으로 안전하게 만드는 것은 아니다. policy design 자체가 새로운 운영 complexity가 된다.

**Trend direction:** **Growing rapidly**

**Maturity:** **Production practice**

**Sources:** [GitHub](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/) · [Reuters/Microsoft MXC](https://www.reuters.com/business/microsoft-nvidia-ceos-unveil-new-ai-laptop-san-francisco-event-2026-10-07/)

## 2. Small-model subagent routing이 비용 최적화의 핵심 패턴으로 부상

**What it is:** reasoning-heavy main agent와 별도로 summarization, compaction, classification, search triage, quick edit 같은 좁은 task를 cheap/fast model에 위임하는 구조다.

**Problem it addresses:** long-running agent와 multi-agent workflow는 token usage와 latency가 빠르게 누적된다.

**How developers are using it:** Anthropic은 Haiku 5.5를 subagent와 high-volume workload에 직접 포지셔닝했고, GitHub Copilot도 Haiku 5.5를 subagent·quick edit·terminal task용 모델로 제공하기 시작했다.

**What changed recently:** 작은 모델의 coding capability와 가격이 개선되면서 '작은 모델 = 단순 fallback'이 아니라 orchestration의 정상적인 worker tier가 되고 있다.

**Evidence / limitations:** Anthropic과 GitHub의 초기 성능 비교는 vendor testing이다. 실제 repository별 quality/cost frontier는 독립 eval이 필요하다.

**Trend direction:** **Growing**

**Maturity:** **Emerging → Production practice**

**Sources:** [Anthropic](https://www.anthropic.com/claude-haiku-5-5) · [GitHub Copilot](https://github.blog/changelog/2026-10-07-claude-haiku-5-5-in-github-copilot/)

## 3. Hybrid local/cloud agent routing이 실제 CLI 기능으로 구체화

**What it is:** cloud frontier model과 local Ollama/model을 한 agent runtime에서 선택하거나 task별로 분배하는 방식이다.

**Problem it addresses:** source-code privacy, cloud cost, latency, offline/air-gapped 요구와 frontier capability를 동시에 만족시키기 어렵다는 문제다.

**How developers are using it:** GitHub Copilot CLI 1.0.94-0부터 /model picker가 local Ollama의 tool-calling model을 발견할 수 있다. Microsoft 역시 Copilot이 일부 task를 local model에 위임하고 어려운 작업은 cloud로 보내는 hybrid 방향을 공개했다.

**What changed recently:** local model 사용이 별도 experimental stack이 아니라 mainstream coding-agent UX 안으로 들어오고 있다.

**Evidence / limitations:** Copilot에서 local model을 선택했다고 자동으로 offline이 되는 것은 아니며 telemetry와 remote provider 설정을 별도로 확인해야 한다. local model quality도 task별 편차가 크다.

**Trend direction:** **Growing**

**Maturity:** **Emerging production feature**

**Sources:** [GitHub Copilot CLI](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/) · [Reuters/Microsoft](https://www.reuters.com/business/microsoft-nvidia-ceos-unveil-new-ai-laptop-san-francisco-event-2026-10-07/)

## 4. General LLM 대신 narrow security model을 pipeline에 삽입

**What it is:** general-purpose coding model이 아니라 secret detection처럼 좁은 task에 fine-tuned된 모델을 development pipeline에 삽입하는 패턴이다.

**Problem it addresses:** password나 credential은 항상 정형 token format을 갖지 않아 regex/static detector만으로 놓칠 수 있다.

**What changed recently:** GitHub는 surrounding code context를 읽어 likely credential을 탐지하는 purpose-built model을 secret scanning alerts, push protection, Copilot security review에 확대하고 있다.

**Evidence / limitations:** context-aware detection은 recall을 높일 수 있지만 false positive/negative가 사라지는 것은 아니다. 일부 기능은 private preview이고 AI Credit consumption도 고려해야 한다.

**Trend direction:** **Growing**

**Maturity:** **Production + Preview mix**

**Sources:** [GitHub](https://github.blog/changelog/2026-10-07-purpose-built-model-for-leaked-secret-detection/)

# Session 3 — AI for Firmware & Embedded Engineering

## 1. Firmware agent sandbox는 'PC sandbox + hardware permission layer'의 2단 구조가 필요

**Firmware interpretation:** Copilot/MXC식 sandbox는 source tree, network, credential, local MCP access를 제한하는 outer boundary로 사용할 수 있다. 그러나 firmware에서는 USB debug probe, serial port, programmer, power control 같은 physical capability가 별도 위험 surface다.

**Practical workflow:** AI agent → OS sandbox → firmware MCP/tool gateway → SWD/JTAG/UART/flash tool → target board 구조로 나누고, read-only observation과 destructive action을 분리한다.

**Useful tools / interfaces:** GitHub Copilot local sandbox/MXC, OpenOCD, J-Link, CMSIS-SVD, ELF/DWARF, RTT/UART, firmware MCP gateway.

**Benefits:** source/credential 유출 위험과 hardware damage 위험을 서로 다른 policy layer에서 다룰 수 있다.

**Limitations / risks:** OS sandbox가 mass erase, option byte, OTP/eFuse write를 자동으로 이해하지는 못한다. hardware-aware permission이 반드시 추가돼야 한다.

**Evidence / maturity:** **Production sandbox primitive + emerging firmware integration pattern**

**Sources:** [GitHub local sandbox](https://github.blog/changelog/2026-10-07-local-sandboxing-for-github-copilot-now-generally-available/) · [jlink-mcp](https://github.com/Klievan/jlink-mcp/)

## 2. Local model routing은 firmware IP 보호에 특히 유용하지만 'local = private'로 단정하면 안 됨

**Firmware interpretation:** proprietary firmware source, board configuration, register map을 외부 API에 보내기 어려운 조직에서는 local model을 linting, summarization, simple refactor, log classification에 배치하고 복잡한 reasoning만 승인된 cloud model로 보내는 구조가 현실적이다.

**Practical workflow:** local Ollama worker → build/static analysis/log triage → 필요 시 sanitized context만 frontier model로 escalation.

**Benefits:** 반복 task의 cloud token cost와 source-code exposure를 줄일 수 있다.

**Limitations / risks:** Copilot CLI의 local model discovery는 offline mode와 동일하지 않다. telemetry, provider endpoint, MCP network access를 별도로 검토해야 한다.

**Evidence / maturity:** **Emerging production feature**

**Sources:** [GitHub Copilot CLI local models](https://github.blog/changelog/2026-10-07-discover-local-models-in-github-copilot-cli/)

## 3. Vendor knowledge + deterministic toolchain pattern이 MCU 개발에도 확산

**Firmware interpretation:** Microchip의 MPLAB AI Coding Assistant처럼 vendor datasheet/toolchain context를 AI assistant에 연결해 MCU migration, code adaptation, error analysis를 돕는 방식이다. generic web RAG보다 target-specific documentation과 IDE/debugger integration이 중요하다.

**Practical workflow:** device selection/migration → vendor datasheet/context → code adaptation → build/debug → hardware validation.

**Useful tools / interfaces:** MPLAB Tools for VS Code, MPLAB AI Coding Assistant, MCC/Harmony, programmer/debugger, MicroCHECK.

**Benefits:** MCU-specific register/peripheral knowledge와 toolchain workflow를 같은 개발환경에 묶을 수 있다.

**Limitations / risks:** AI-generated code가 compile된다고 electrical/timing correctness가 보장되는 것은 아니다. vendor ecosystem lock-in과 stale documentation 문제도 남는다.

**Evidence / maturity:** **Vendor-supported development tooling**

**Sources:** [Microchip MCU migration and AI Coding Assistant](https://www.microchip.com/en-us/products/microcontrollers/32-bit-mcus/migration)

## 4. Edge AI deployment도 MCP를 통한 model/tool discovery로 이동

**Firmware interpretation:** Arm AI Portal은 coding agent가 MCP를 통해 target hardware별 model, runtime, memory/performance 정보를 찾아 deployment workflow를 구성하게 한다. 이는 embedded AI에서 model selection과 quantization/deployment knowledge를 agent tool로 구조화하는 방향이다.

**Practical workflow:** task 정의 → target hardware 선택 → model 후보 비교 → memory/performance 검토 → runtime/quantization workflow → deploy/test.

**Benefits:** model 선택을 단순 leaderboard가 아니라 실제 target memory·runtime·performance constraint에 연결한다.

**Limitations / risks:** portal의 지원 hardware/runtime 범위를 벗어나는 custom NPU/PIM에서는 여전히 자체 compiler/runtime knowledge와 실측 데이터가 필요하다.

**Evidence / maturity:** **Production developer portal / emerging agentic workflow**

**Sources:** [Arm AI Portal](https://developer.arm.com/ai)
