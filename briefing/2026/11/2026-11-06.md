# Session 3 — AI for Firmware & Embedded Engineering

### 1. Fail-closed firmware HIL pipeline
**Firmware interpretation:** Agent가 컴파일 성공 후 임의 보드에 flash하지 못하도록 build와 destructive action을 분리한다.

**Practical workflow:** edit → cross-compile → ELF/HEX hash 기록 → 대상 보드 확인 → 승인된 flash → UART/SWD capture → pytest 판정 → 실패 시 중단.

**Useful tools / interfaces:** CMake, arm-none-eabi-gcc, OpenOCD, ST-LINK, pyserial, pytest, labgrid.

**Benefits:** 펌웨어 수정의 재현성과 추적성을 높인다.

**Limitations / risks:** option byte, mass erase, 전원 제어는 별도 승인; 보드 상태·타이밍 차이로 flaky test가 발생할 수 있다.

**Evidence / maturity:** 기존 HIL 도구에 agent 권한 경계를 적용한 설계 제안 / Experiment.

**Sources:** [labgrid](https://github.com/labgrid-project/labgrid) · [OpenOCD](https://openocd.org/)

### 2. PSCP와 BLE CoC의 deterministic protocol oracle
**Firmware interpretation:** LLM이 패킷을 '정상'이라고 판정하는 대신 SLIP framing, CBOR decoding, CRC16-XMODEM, ACK/NACK 및 timeout의 명시적 불변식을 검증한다.

**Practical workflow:** host-side property test → malformed frame fuzzing → STM32WBA ThreadX/PS-Link 실보드 테스트 → disconnect/reconnect와 queue exhaustion 측정.

**Useful tools / interfaces:** Hypothesis, libFuzzer, pytest, pyserial, ThreadX trace.

**Benefits:** 경계 조건·회귀 오류를 자동 검출하고 AI agent의 수정 결과를 객관적으로 평가한다.

**Limitations / risks:** host simulation은 DMA/IRQ race와 전원 이상을 완전히 재현하지 못한다.

**Evidence / maturity:** 프로토콜 테스트 기술은 Production practice; agent 결합은 Emerging practice.

**Sources:** [Hypothesis](https://hypothesis.readthedocs.io/) · [LLVM libFuzzer](https://llvm.org/docs/LibFuzzer.html)
