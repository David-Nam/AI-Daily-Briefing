# Session 3 — AI for Firmware & Embedded Engineering

## Firmware Harness Engineering

권장 검증 파이프라인

AI Code Edit

Cross-compile

Flash (승인 필요)

UART / SWD Capture

HIL Test + Evaluation

Pass 또는 수정 후 재검증

STM32WBA, ThreadX, BLE CoC 같은 펌웨어 개발에서는 Agent가 생성한 코드의 컴파일 성공만으로 기능을 검증할 수 없다.

`arm-none-eabi-gcc`, CMake, OpenOCD, pyserial, pytest 등을 조합해 실제 보드에서 결과를 평가하는 구조가 필요하다.

특히 다음과 같은 테스트가 중요하다.

- BLE 연결 해제 및 재연결, queue exhaustion, timeout
- CBOR/SLIP/CRC16-XMODEM의 malformed frame 및 retry
- RTOS thread 우선순위와 race condition
- Flash 대상 확인, 복구 절차, 로그와 firmware hash 보존

Zephyr의 Twister는 실제 보드, fixture, multi-DUT 테스트를 지원하는 참고 구현이다. 다만 AI Agent와의 완전 자동 통합은 별도의 개발 및 검증이 필요하다.
