# Session 3 — AI for Firmware & Embedded Engineering

이번 검색에서는 신규 MCU coding agent의 독립적인 실보드 평가 사례를 충분히 확보하지 못했다. 아래는 확인한 기술 동향과 공식 embedded tooling을 연결한 적용 제안이다.

### 1. Firmware agent 평가용 private regression suite

**Firmware interpretation:** 공개 benchmark 대신 사내 C/C++ 프로젝트의 실제 오류와 고정된 테스트로 agent를 평가한다.

**Practical workflow:** 실패 재현 → 코드 수정 → cross-build → host/simulator test → 승인된 실보드 테스트 → 독립 리뷰. 평가 과정에서 agent가 성공 판정 기준을 임의로 변경하지 못하도록 분리한다.

**Useful tools / interfaces:** Zephyr Twister, Renode, compiler/test runner, CI artifact.

**Benefits:** 프로젝트 특유의 protocol edge case와 peripheral 동작을 평가할 수 있다.

**Limitations / risks:** simulator의 주변장치 모델과 실제 MCU 동작은 다를 수 있다. ISR latency, DMA race, 전력 및 timing 검증에는 실보드가 필요하다.

**Evidence / maturity:** Renode와 Twister는 실제 제공되는 테스트 기반 도구이며, 위 agent 평가 구성은 설계 제안(Experiment)이다.

**Sources:** [Renode testing](https://renode.readthedocs.io/en/latest/introduction/testing.html) · [Zephyr Twister](https://docs.zephyrproject.org/latest/develop/twister/index.html) · [AI benchmark 관련 보도](https://www.techzine.eu/news/devops/146082/open-source-code-may-skew-ai-benchmarks/)

### 2. MCP Skill을 이용한 제한적 HIL harness

**Firmware interpretation:** build, flash, UART capture, test evaluation을 독립된 tool로 정의한다.

**Practical workflow:** build와 로그 읽기는 허용하고, flash는 보드 UID·대상 주소·firmware hash를 검증한 후 승인한다. 보드 lock, 실행 timeout 및 테스트 종료 조건을 설정한다.

**Useful tools / interfaces:** MCP, PreSkillShellCommand, SWD/JTAG, UART, Renode.

**Benefits:** agent가 하드웨어 작업을 표준화된 인터페이스로 요청하고 결과를 반복 검증할 수 있다.

**Limitations / risks:** Hook만으로 직접 shell 실행이나 다른 tool 경로를 통제할 수 있다고 가정하면 안 된다. Flash erase, option bytes, 전원 제어는 장치 측 정책에서도 차단하거나 승인해야 한다.

**Evidence / maturity:** Claude Code의 신규 Hook은 공식 기능이고 HIL 결합은 설계 제안(Experiment)이다.

**Sources:** [Claude Code changelog](https://code.claude.com/docs/en/changelog) · [Renode testing](https://renode.readthedocs.io/en/latest/introduction/testing.html)

### 3. Edge AI 시스템 검증: NPU에서 서비스까지

**Firmware interpretation:** 영상 수집, preprocessing, inference, postprocessing, 결과 전달 전체를 측정한다.

**Practical workflow:** 동일 입력 영상으로 latency p50/p95, frame drop, peak memory, 전력, 장시간 운용 중 오류를 기록한다. 모델과 compiler/runtime 버전, 보드 revision을 고정한다.

**Useful tools / interfaces:** 장치별 profiler, timestamped logs, 전력계측기, 고정 테스트 영상.

**Benefits:** 칩 성능과 실제 서비스 성능의 차이를 발견할 수 있다.

**Limitations / risks:** 단일 데모 영상이나 평균 FPS만으로 안전 감시 성능을 입증할 수 없다. 현장 환경의 오탐·미탐 및 장애 조건도 검증해야 한다.

**Evidence / maturity:** K-Perf 협력과 가스공사 CCTV 도입은 보고된 산업 사례이며, 위 측정 구성은 적용 제안이다.

**Sources:** [K-Perf 협력](https://m.etnews.com/20261126000422) · [가스공사 CCTV](https://www.etnews.com/20261125000441)
