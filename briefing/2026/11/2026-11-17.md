# Session 2 — AI Development Trend Radar

### Agent Harness의 비용·실행 제어
**What it is / Problem:** Agent의 모델 호출뿐 아니라 tool invocation, retry, context와 권한을 실행 계층에서 관리하는 방식이다. 장기 작업의 비용 폭증과 재현성 부족을 줄인다.
**How developers use it:** 작업별 budget, structured logs, test gate, 명시적 승인 절차를 둔다.
**Recent delta / Evidence:** Uber의 Software Factory 사례는 Agent 실행비를 session·turn·request·token 단위로 분해한다. 이번 검색 기간에 이 방식의 새로운 업계 표준화는 확인되지 않았다.
**Direction / Maturity:** Growing / Emerging practice.
**Limitations:** 벤더 내부 사례를 모든 조직의 비용 절감 효과로 일반화할 수 없다.
**Sources:** [Uber Engineering](https://www.uber.com/us/en/blog/efficient-software-factory/)

### Agent 권한과 공급망 보안
**What it is / Problem:** Agent가 repository 지시문, tool output, 외부 콘텐츠를 읽고 shell·network·filesystem을 호출하면서 발생하는 권한 상승 위험이다.
**How developers use it:** 최소 권한, tool allowlist, 격리된 실행환경, 고위험 작업 승인과 audit log를 결합한다.
**Recent delta / Evidence:** Microsoft와 NVIDIA의 기존 기술 자료가 Agent를 별도 보안 주체로 취급해야 한다는 방향을 뒷받침한다. 24시간 내 새 사고가 확인된 것은 아니다.
**Direction / Maturity:** Growing / Emerging practice.
**Limitations:** 정책만으로 prompt injection을 완전히 막을 수 없다.
**Sources:** [Microsoft Security](https://www.microsoft.com/en-us/security/blog/2026/10/19/agents-are-your-newest-insiders-security-must-move-at-their-speed/) · [NVIDIA Technical Blog](https://developer.nvidia.com/blog/where-security-fits-in-an-ai-agent-stack/)

# Session 3 — AI for Firmware & Embedded Engineering

### Cross-compile → Flash → UART → HIL Harness
**Firmware interpretation:** 일반 coding-agent의 테스트 피드백 루프를 실물 보드 검증까지 확장한다.
**Practical workflow:** Agent가 patch 생성 → CMake 빌드 → static analysis → 사람이 Flash 승인 → OpenOCD 또는 vendor programmer 실행 → pyserial 로그 수집 → pytest assertion 평가.
**Tools / Benefits:** CMake, OpenOCD, pyserial, pytest; 반복 가능한 실패 재현과 regression 검출.
**Risks:** Flash erase·option bytes·전원 제어는 장치 손상 가능성이 있어 기본적으로 자동 실행을 금지한다. UART 문자열 일치만으로 timing·race condition을 검증할 수 없다.
**Evidence / Maturity:** 기술적으로 실현 가능한 설계 제안 / Experiment. 오늘 새로 검증된 양산 사례로 제시하지 않는다.
**Sources:** [OpenOCD](https://openocd.org/) · [pytest](https://docs.pytest.org/)

### RTOS Agent 평가 기준
**Firmware interpretation:** Agent가 수정한 ThreadX/FreeRTOS 코드에 대해 기능 테스트와 자원·시간 제약 검증을 분리한다.
**Practical workflow:** build 결과와 함께 stack watermark, task starvation, ISR latency, timeout, watchdog reset을 수집한다.
**Tools / Benefits:** RTOS trace, UART/SWD, CI artifact; 단순 compile 성공을 넘어 시스템 안정성의 회귀를 찾는다.
**Risks:** HIL 환경의 비결정성, 불충분한 test oracle, 보드별 편차가 있다.
**Evidence / Maturity:** 적용 제안 / Experiment.
**Sources:** [Zephyr Testing](https://docs.zephyrproject.org/latest/develop/test/index.html)
