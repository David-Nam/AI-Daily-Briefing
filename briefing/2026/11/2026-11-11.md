# Session 2 — AI Development Trend Radar

### 1. Harness Engineering: 실행 환경과 복구 가능성 중심
**What it is / Problem:** 장시간 agent가 문맥을 잃거나 실패한 상태에서 작업을 이어가지 못하는 문제를 실행 환경, 진행 기록, 테스트로 해결한다.
**How developers use it:** 작은 단위의 계획, 작업 상태 기록, 테스트 실행, 실패 원인 재주입을 반복한다.
**What changed recently:** DeepSeek Harness 0.2.2-rc.1 관련 보도에서 Git worktree와 다른 coding agent에 대한 실험적 위임 기능이 소개됐다. 해당 기능은 독립적으로 검증된 생산성 개선으로 보지 않는다.
**Evidence / limitations:** Anthropic의 장기 실행 agent 연구는 설계 근거를 제공하지만, 실제 팀 생산성은 작업·테스트 품질에 좌우된다.
**Trend direction:** Growing. **Maturity:** Emerging practice.
**Sources:** [Anthropic 연구](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) · [DeepSeek Harness 보도](https://pasqualepillitteri.it/en/news/30977/deepseek-harness-022-delegates-codex-claude)

### 2. Worktree 기반 병렬 agent와 위임
**What it is / Problem:** 여러 agent가 동일 작업 디렉터리를 수정할 때 생기는 충돌을 격리한다.
**How developers use it:** 작업별 Git worktree를 만들고 각 agent가 독립적으로 구현·테스트한 후 사람이 diff를 검토한다.
**What changed recently:** DeepSeek Harness의 release candidate에서 worktree와 Codex·Claude 위임 실험이 보도됐다.
**Evidence / limitations:** 파일 충돌은 줄일 수 있지만 설계 충돌, merge 비용, 토큰 사용량은 오히려 증가할 수 있다.
**Trend direction:** Growing / Fragmenting. **Maturity:** Experiment to emerging practice.
**Sources:** [DeepSeek Harness 보도](https://pasqualepillitteri.it/en/news/30977/deepseek-harness-022-delegates-codex-claude) · [Anthropic 연구](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)

# Session 3 — AI for Firmware & Embedded Engineering

### 1. 제한된 firmware harness
**Firmware interpretation:** edit → cross-compile → static analysis → unit test → UART log evaluation → review 순으로 agent의 피드백을 구성한다.
**Practical workflow:** STM32 프로젝트에서 build 명령과 경고 기준을 고정하고, 실패 로그를 agent에 반환하되 flash는 별도 승인 단계로 둔다.
**Useful tools / interfaces:** CMake, arm-none-eabi-gcc, clang-tidy, pytest, pyserial, GitHub Actions 또는 사내 runner.
**Benefits:** 반복 빌드 오류와 회귀 분석을 자동화한다.
**Limitations / risks:** 빌드 성공은 타이밍·전력·하드웨어 안전성 검증을 대체하지 못한다. Flash/option bytes 변경은 수동 승인한다.
**Evidence / maturity:** 기존 CI 도구를 결합한 실무 적용 제안이며, 최근 검증된 특정 firmware agent 제품 성능 주장은 아니다.
**Sources:** [Anthropic harness 연구](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)

### 2. RTOS 및 통신 프로토콜에 대한 eval-driven development
**Firmware interpretation:** ThreadX/FreeRTOS의 경쟁 상태와 CBOR/SLIP 프레이밍을 명세 기반 테스트로 평가한다.
**Practical workflow:** 경계 길이, CRC 오류, 타임아웃, 재연결, queue overflow 테스트를 생성하고 host-side test에서 통과한 변경만 보드에 올린다.
**Useful tools / interfaces:** pytest, hypothesis, serial console, SWD/JTAG, CI artifact.
**Benefits:** agent가 만든 코드의 정확성을 재현 가능한 입력으로 검증한다.
**Limitations / risks:** ISR 타이밍과 실제 RF/USB 오류는 host simulation만으로 충분히 재현되지 않는다.
**Evidence / maturity:** 기술적으로 타당한 권장 workflow; 최근 대규모 현장 채택을 입증하는 자료는 확인되지 않았다.
**Sources:** [Anthropic harness 연구](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)
