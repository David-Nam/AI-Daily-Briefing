# Session 3 — AI for Firmware & Embedded Engineering

### 1. Flash 권한을 분리한 HIL coding harness
**Firmware interpretation:** Agent가 firmware patch를 작성하더라도 장치 flash와 option byte 변경은 승인된 별도 단계에서만 수행한다.
**Practical workflow:** edit → arm-none-eabi-gcc cross-compile → static analysis → artifact hash → board identity check → 승인된 flash → UART/SWD capture → pytest oracle.
**Useful tools / interfaces:** CMake, OpenOCD, pyOCD, pyserial, pytest, labgrid.
**Benefits:** 변경의 추적성과 재현성을 높이고 잘못된 장치에 flash하는 위험을 줄인다.
**Limitations / risks:** HIL flaky timing, 보드 상태 편차, mass erase·option byte의 비가역적 위험.
**Evidence / maturity:** 기존 도구를 조합한 설계 제안 / Experiment.
**Sources:** [labgrid](https://github.com/labgrid-project/labgrid) · [OpenOCD](https://openocd.org/)

### 2. PSCP와 ThreadX BLE CoC의 결정적 검증
**Firmware interpretation:** Agent의 패킷 처리 변경을 자연어 판단이 아니라 CRC16-XMODEM, SLIP escaping, CBOR, ACK/NACK, timeout 불변식으로 검증한다.
**Practical workflow:** host-side property testing → malformed frame fuzzing → 보드별 RX/TX throughput·disconnect 반복 측정 → trace 비교.
**Useful tools / interfaces:** Hypothesis, libFuzzer, ThreadX trace, pyserial.
**Benefits:** 프로토콜 경계 오류와 회귀를 빠르게 탐지한다.
**Limitations / risks:** Host simulation은 DMA/IRQ race와 RF 환경을 완전히 재현하지 못한다.
**Evidence / maturity:** 검증 기술은 Production practice, agent 연계는 Experiment.
**Sources:** [LLVM libFuzzer](https://llvm.org/docs/LibFuzzer.html) · [ThreadX](https://github.com/eclipse-threadx/threadx)
