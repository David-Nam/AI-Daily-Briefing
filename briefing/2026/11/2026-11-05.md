# Session 3 — AI for Firmware & Embedded Engineering

### 1. Fail-closed HIL harness
**Firmware interpretation:** Agent가 flash, reset, option byte 변경을 실행할 때 실패한 안전 검사 이후 작업을 계속해서는 안 된다.
**Practical workflow:** edit → host test → cross-compile → artifact hash 확인 → 승인된 flash → UART/SWD 수집 → pytest 판정 → 실패 시 중단 및 로그 보존.
**Tools / interfaces:** OpenOCD, ST-LINK, pyserial, pytest, self-hosted runner, 제한된 MCP tool.
**Benefits:** 빌드 성공과 보드 동작 성공을 분리하고 회귀를 재현할 수 있다.
**Limitations / risks:** 전원·RF·타이밍 변동, 잘못된 target 선택, flash 손상. 옵션 바이트와 대량 erase는 자동 허용하지 않는다.
**Evidence / maturity:** 기존 HIL 도구에 최근 agent 정책을 적용한 제안 설계 / Experiment.
**Sources:** [labgrid](https://github.com/labgrid-project/labgrid) · [Claude Code Releases](https://github.com/anthropics/claude-code/releases)

### 2. RTOS/PSCP 프로토콜 검증을 deterministic oracle로 분리
**Firmware interpretation:** ThreadX BLE CoC와 PS-Link의 CBOR·SLIP·CRC16-XMODEM은 LLM의 자연어 평가보다 명시적 property test가 적합하다.
**Practical workflow:** malformed frame fuzzing → ACK/NACK 상태 전이 검사 → disconnect/reconnect → thread 자원 누수 확인 → 실보드 trace 비교.
**Tools / interfaces:** libFuzzer, Hypothesis, CTest, pyserial, GDB, ThreadX trace.
**Benefits:** parser boundary와 상태 전이 회귀 검출.
**Limitations / risks:** host simulation이 실제 interrupt timing·DMA race를 재현하지 못할 수 있다.
**Evidence / maturity:** 검증 기술은 성숙; agent 통합은 제안 / Emerging practice.
**Sources:** [libFuzzer](https://llvm.org/docs/LibFuzzer.html) · [Hypothesis](https://hypothesis.readthedocs.io/)

### 3. Agent 작업 환경의 네트워크 파일시스템 안정성
**Firmware interpretation:** NAS/NFS에 있는 firmware workspace와 장시간 CLI 작업에서 설정 파일이 일시적으로 사라지거나 오래된 상태로 읽히는 문제가 CI 신뢰성을 낮춘다.

**Tools / interfaces:** Claude Code 2.1.318, NFS, self-hosted runner, CI artifact manifest.
**Benefits:** 설정 유실과 비결정적 실패를 추적하기 쉽다.
**Limitations / risks:** Claude의 수정이 모든 NFS 장애를 해결하는 것은 아니다.
**Evidence / maturity:** 공식 수정 내역 / Production reliability practice.
**Sources:** [Claude Code Releases](https://github.com/anthropics/claude-code/releases)
