# Session 3 — AI for Firmware & Embedded Engineering

### 1. Firmware harness: cross-compile과 실물 보드 검증의 폐루프
**Firmware interpretation:** edit → cross-compile → static analysis → flash → UART capture → hardware assertions → retry.
**Practical workflow:** Agent에게 C/C++ 변경을 맡기되 컴파일은 격리된 runner에서 수행한다. 보드별 flash는 명시 승인 후 실행하고 UART·전류·타이밍 로그를 구조화해 결과를 판정한다.
**Useful tools / interfaces:** CMake, arm-none-eabi-gcc, OpenOCD, pyserial, pytest, GitHub Actions 또는 self-hosted runner.
**Benefits:** 재현 가능한 오류 수집, 반복 회귀 테스트, 수정 후 검증 시간 절약.
**Limitations / risks:** flash 실패, 보드 손상, watchdog과 전원 타이밍의 비결정성, 약한 테스트 oracle.
**Evidence / maturity:** 기존 자동화 도구를 결합한 실무 설계 제안이며 특정 AI agent의 HIL 성공률을 입증한 사례는 아니다.
**Sources:** [OpenOCD](https://openocd.org/) · [pytest](https://docs.pytest.org/)

### 2. Datasheet-aware coding과 register-level 검증
**Firmware interpretation:** PDF에서 추출한 register 설명은 참고 context이고 최종 판단은 원본 reference manual과 실측 결과를 기준으로 한다.
**Practical workflow:** HAL 변경 시 MCU part number, silicon revision, register offset, bit mask, reset value, errata를 근거와 함께 기록하고 컴파일·테스트한다.
**Useful tools / interfaces:** CMSIS-SVD, vendor HAL, clang-tidy, Cppcheck.
**Benefits:** 반복적인 초기화 코드 검토와 주변장치 설정 차이 탐지.
**Limitations / risks:** PDF 파싱 오류, silicon revision 불일치, reserved bit 오기입, 하드웨어 부작용.
**Evidence / maturity:** AI-assisted review는 실험적; 정적 분석과 vendor 문서 대조는 성숙한 관행.
**Sources:** [CMSIS](https://github.com/ARM-software/CMSIS_5) · [Cppcheck](https://cppcheck.sourceforge.io/)

### 3. RTOS·프로토콜 테스트에 agent 활용
**Firmware interpretation:** RTOS task 상태, race, timeout, packet corruption을 agent가 로그에서 가설화하고 테스트를 생성한다.
**Practical workflow:** host-side protocol fuzz → target build → UART/USB transport test → fault injection → deterministic assertions.
**Useful tools / interfaces:** ThreadX/FreeRTOS, pytest, libFuzzer, pyserial, OpenOCD.
**Benefits:** CRC, framing, timeout, retry, link drop 경계 조건의 회귀 범위 확대.
**Limitations / risks:** 시뮬레이션에서 발견되지 않는 DMA·interrupt race와 하드웨어 타이밍 문제.
**Evidence / maturity:** 테스트 도구는 성숙; agent 자동 원인 분석의 정확도는 프로젝트별 검증 필요.
**Sources:** [libFuzzer](https://llvm.org/docs/LibFuzzer.html) · [FreeRTOS](https://www.freertos.org/)
