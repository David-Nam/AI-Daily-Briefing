# Session 2 — AI Development Trend Radar

### 1. Harness Engineering: 모델보다 실행 환경 설계
**What it is:** Agent loop, tool interface, context, permissions, orchestration을 하나의 실행 시스템으로 설계하는 접근이다.
**Problem it addresses:** 모델이 생성한 변경을 안전하고 반복 가능하게 실행·검증하기 어렵다는 문제.
**How developers are using it:** 명시적 tool contract, deterministic retrieval, CI 기반 피드백 루프를 구성한다.
**What changed recently:** 11개 coding harness의 소스 분석 연구는 공통 설계 패턴과 구현 차이를 체계화했다. 오늘 새 릴리스라는 뜻은 아니다.
**Evidence / limitations:** 연구는 실제 코드 구조를 분석했지만 성능 우위를 직접 입증하는 실험은 아니다.
**Trend direction:** growing. **Maturity:** Emerging practice.
**Sources:** [Harness Engineering 연구](https://arxiv.org/abs/2609.00006)

### 2. Agent configuration supply-chain 보안
**What it is:** Skills, hooks, MCP 설정과 instruction 파일을 실행 권한이 있는 의존성으로 다루는 접근이다.
**Problem it addresses:** 편리한 agent 설정이 과도한 shell 권한이나 검증되지 않은 서버 실행으로 이어질 수 있다.
**How developers are using it:** 버전 고정, 실행 허용 목록, 변경 리뷰, 격리된 테스트를 적용한다.
**What changed recently:** 3,171개 공개 저장소를 분석한 연구가 설정 결함을 실증했다. 표본의 16.0%에서 보안 결함을 확인했으나 자격증명 유출 경로를 입증한 것은 아니다.
**Evidence / limitations:** 공개 GitHub 표본이 전체 기업 환경을 대표하지는 않는다.
**Trend direction:** growing. **Maturity:** Emerging practice.
**Sources:** [Scanning the Harness](https://arxiv.org/abs/2609.07360)

# Session 3 — AI for Firmware & Embedded Engineering

### 1. Hardware-in-the-loop agent 평가
**Firmware interpretation:** edit → cross-compile → flash → UART/log capture → measurement → evaluate → retry.
**Practical workflow:** 에이전트가 수정안을 만들고, CI가 격리된 빌드를 실행한 뒤 승인된 장비에서 flash와 측정을 수행한다.
**Useful tools / interfaces:** OpenOCD, pyOCD, serial logging, gRPC HIL API.
**Benefits:** 빌드 성공을 넘어 전류·온도·실제 동작을 검증할 수 있다.
**Limitations / risks:** 잘못된 flash, 전원 설정, 타이밍 의존성, 보드 상태 오염을 방지해야 한다. 쓰기 작업에는 별도 승인과 복구 경로가 필요하다.
**Evidence / maturity:** EmbeddedArena는 실제 하드웨어 지표를 활용하는 공개 benchmark로, 연구·실험 단계다.
**Sources:** [EmbeddedArena](https://github.com/ubicomplab/embedded-arena) · [EdgeEmbed HIL SDK](https://edgeembed.com/docs/hil-sdk/)

### 2. Firmware agent의 도구 권한 경계
**Firmware interpretation:** MCU 레지스터 쓰기, flash erase, 전원 제어를 일반 파일 읽기와 다른 위험 등급으로 분류한다.
**Practical workflow:** 데이터시트 검색과 빌드는 기본 허용, flash/erase와 전원 제어는 승인 및 대상 보드 확인 후 실행한다.
**Useful tools / interfaces:** AGENTS.md, CLAUDE.md, restricted tool wrappers, CI allowlists.
**Benefits:** 자동화 속도를 유지하면서 물리적 손상과 비가역 변경 위험을 줄인다.
**Limitations / risks:** 모델 판단만으로 전압·전류 안전 한계를 보장할 수 없다.
**Evidence / maturity:** Harness 보안 연구에 근거한 firmware 적용 제안이며, 독립적인 생산 현장 효과는 검증되지 않았다.
**Sources:** [Scanning the Harness](https://arxiv.org/abs/2609.07360)
