# AI Daily Briefing 실행 지시문

대상 저장소: David-Nam/AI-Daily-Briefing
기본 브랜치: main
날짜와 시간대: Asia/Seoul

## 실행 전

1. 저장소 파일을 읽고 기존 브리핑을 확인한다. samples/ 파일은 실제 결과로 취급하지 않는다.
2. 기존 AI Daily Briefing의 관심 분야, 언어, 구성, 출처 규칙이 제공되어 있으면 그대로 적용한다. 없으면 한국어로 AI 모델·제품 발표, 개발자 도구, 오픈소스의 검증된 주요 변화를 정리한다.
3. 오늘 날짜의 briefing/YYYY/MM/YYYY-MM-DD.md가 이미 있고 status: complete이면 내용을 확인한 후 중복 실행을 종료한다. 기존 파일을 자동으로 덮어쓰지 않는다.
4. 접근·검색·쓰기 기능이 없으면 실패 원인을 알린다. 저장하지 못한 결과를 성공으로 보고하지 않는다.

## 조사 및 작성

- 실행 시작 시각을 coverage_end로 정한다.
- 이전 실제 브리핑의 coverage_end를 읽는다. 있으면 max(24시간, 그 시점 이후 경과시간)을 조사 범위로 삼고, 없으면 최근 24시간을 조사한다.
- 공식 발표, 원문 문서, 릴리스 노트 등 일차 출처를 우선한다. 각 주요 항목의 원문을 열어 날짜와 사실을 확인한다.
- 기사 게시일과 실제 사건 날짜를 구분한다. 이전 브리핑의 반복 내용은 새로운 변화가 있을 때만 포함한다.
- 확인된 사실과 해석을 구분한다. 중요한 소식이 없으면 없다고 작성하며 내용을 만들어 채우지 않는다.
- samples/2026-10-02.md의 구성을 참고한다. YAML에는 date, timezone, status: complete, generated_at, coverage_start, coverage_end를 넣는다. 시각은 시간대 오프셋을 포함한 ISO 8601 형식으로 적는다.
- 실제 브리핑은 briefing/YYYY/MM/YYYY-MM-DD.md에 UTF-8 Markdown으로 저장한다. 원문 링크는 일반 Markdown 링크로 기록한다.

## GitHub 저장 및 완료

- 사용 가능한 GitHub 파일 생성 도구로 main에 새 파일을 생성한다. 로컬 실행인 경우 최신 원격 상태를 확인하고, 해당 브리핑 파일만 커밋하여 main에 일반 push한다.
- 다른 변경을 함께 커밋하거나 force push하지 않는다.
- 충돌이나 원격에 이미 있는 파일은 다시 읽어 확인한다. 임의로 덮어쓰지 않는다.
- 저장 후 원격의 파일을 다시 읽어 제목, 날짜, 본문, 출처 링크가 기록되었는지 확인한다.
- 성공하면 브리핑 핵심 요약, 저장된 GitHub 파일 링크, 커밋 식별자를 알린다. 실패하면 실패 단계와 재시도에 필요한 조치를 알린다.
